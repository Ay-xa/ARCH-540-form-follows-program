## 状态词汇（每个数值和规则都要带一个）
| 状态 | 含义 |
|---|---|
| 已核实 | 来自温哥华官方文件或可核对的原文，我读到了 |
| 来源待核对 | 有来源，但我只看到摘要或二手转述 |
| 借用 | 借自其他城市的标准，温哥华是否适用未证实 |
| 推断 | 根据文献推出来的，不是文献直接给的 |
| 假设 | 我按常识或常见大小划的，没有来源 |
| 用户定义 | 你定义的概念 |
| 用户决定 | 你做的设计决定 |
| 用户设定 | 你修改过的数值（写日期） |

## 原则
1. 数字由代码计算，AI 负责理解、解释和提建议。
2. 不编造规则、数值。找不到来源就标“假设”。
3. 借用的、假设的值，在结果旁标明。
4. 改规则或数值时，写明日期和理由。

## Skill 的结构设想（2026-10-17 讨论，2026-10-21 补记）
用户的计划：**先把文档做完整，规则稳定后再做成 skill**（skill = 给 AI 助手读的一份说明加数据，让它每次按同样的规则做事）。至今没有做。

**为什么要做成 skill：** 让 AI 每次按同一套规则工作；规则放在可读、可改的文件里，不藏在代码或对话里；把“不编造数值”写成硬规定。用户 2026-10-17 评价前六条规则：“很好，可以列成 skill”。

**skill 不是计算引擎。** 数字仍由程序算，skill 只管 AI 怎么读数据、怎么问、怎么解释。

**三层结构：**
| 层 | 内容 | 现在对应的文件 |
|---|---|---|
| 数据层 | 功能库、规则、阈值，每项带来源和状态标签 | 本文件夹的 `FUNCTION_LIBRARY.md`、`STAGE_RULES.md`、`PLACEMENT_CRITERIA.md` |
| 确定性的计算层 | 分区、阶段匹配、面积检查、分配、未生成的原因 | `Version_01/index.html` 里的代码 |
| 给 AI 的说明 | 读数据；向用户提问；解释排布；提出功能调整；用库里的十个问题分析新功能 | 还没有写 |
